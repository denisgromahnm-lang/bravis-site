# BRAVIS — приёмка опубликованного сайта

Состояние на 28 октября 2026 года. Основной сайт: https://bravisrest.ru/. Сайт опубликован в существующем Timeweb App 278139. GitHub Pages — отдельный предпросмотр с `noindex`.

## Что работает

- Шесть страниц: главная, меню, бизнес-ланч, банкеты, контакты, политика данных.
- Утверждённые печатные меню и фотографии интерьера. Фотографии блюд из старого меню не возвращать. Проект нового ассортимента из другой задачи не является утверждённым меню для публикации.
- Ланч по пяти будням, доступные клавиатурные вкладки и все дни без JavaScript.
- Мобильная шапка с доступом к меню, нижние кнопки и возврат наверх; учтены короткие экраны и уведомление об аналитике.
- Проверенные Telegram, VK, Instagram, WhatsApp и Telegram для сообщений. MAX: аккаунт «Рабочий Бравис» и рабочий номер подтверждены адресной проверкой; иконка ведёт к инструкции поиска по номеру с копированием. Прямой публичный URL профиля пока не подтверждён. Сообщества и Viber не выдумывать.
- Карточка Яндекс Карт, рейтинг 5,0 и «Хорошее место · 2026», проверенные 28 октября; дата указана на сайте. Официальные карта и рейтинг загружаются по отдельному нажатию.
- SmartReserve открывает BRAVIS на Расковой, 20 и показывает доступные интервалы. Проверено в браузере 28 октября; контрольная бронь не создавалась.
- Ссылки на доставку Яндекс Еды и регистрацию карты Loona. Не создавать новые платные сервисы для этих переходов.
- Метрика 113768615 только после согласия. Приём `menu_open`, `phone_click`, `reserve_click` подтверждён серверным отчётом; эти три цели сохранены источником конверсий в Директе. Кампании не запускались.
- HTTPS, canonical, HTML-контент, robots/sitemap и Restaurant JSON-LD. `www` → основной домен 308 с сохранением пути и меток; HTTP www использует два корректных перехода. Gzip включён, неизвестные пути возвращают настоящий 404, SPA Fallback выключен.

## Открытые условия полного завершения

1. **Политика данных.** Опубликованный файл `content/privacy.approved.html` содержит формулировки рабочего проекта и неподтверждённые условия обработки. `legalPolicyApproved=true` в старой production-конфигурации не устраняет этот пробел. Нужны проверенная фактическая схема и окончательная редакция оператора. Проверка готовности теперь выявляет этот пункт.
2. **Сквозная аналитика.** Связи SmartReserve booking_id → визит → оплаченный чек в существующем общем iiko producer нет. В разделе «Гости» контакты скрыты до согласия, кассовая интеграция в проверенном кабинете отмечена «Скоро». Координатор подтвердил внешний блокер. Не создавать второй iiko auth/адаптер, не передавать фиктивные суммы/контакты. Подробности — `ANALYTICS_SEO.md`.
3. **Яндекс Вебмастер.** Права подтверждены, но ручная отправка sitemap блокируется режимом «Только для чтения» сервиса. Последняя проверка 28 октября подтверждает недоступность кнопки добавления. Публичный sitemap уже доступен поисковику через robots.txt.
MAX доступен гостям через `/contacts/#max-contact`: подтверждённый аккаунт, номер и официальная инструкция поиска. Номер можно скопировать кнопкой или выделить без JavaScript. При появлении подтверждённого публичного share URL можно заменить инструкцию прямым переходом; внутренний адрес web.max.ru и выдуманные ссылки не использовать.

Google Search Console — отдельное необязательное подключение при наличии доступа; оно не является условием технической индексации в Яндексе. Трансфер регистратора и новая корпоративная почта не нужны для работы текущего сайта и в этом выпуске не выполнялись. Используется подтверждённая почта `bravis.msk@mail.ru`.

## Сборка и обновление

Конфигурация предпросмотра остаётся в `site.config.json`. Параметры основного сайта — в `production.config.json`; не включать индексацию предпросмотра ради отчёта о готовности.

```bash
python3 site/scripts/check_launch_readiness.py --production --strict
python3 site/scripts/build_timeweb_release.py --output /tmp/bravis-NEW-release
```

Строгая проверка намеренно возвращает код 2, пока открыто обязательное условие. Для предпросмотра запустить без `--production`; его `noindex` ожидаем.

Timeweb использует ветку `production-timeweb`, папку `/production` и build directory `.`. Подключение публичного URL репозитория не даёт автоматического деплоя: выбрать точный production-коммит в существующем App и применить его. После публикации сравнить HTTP/TLS и SHA256 HTML/JS/CSS основного домена с локальным выпуском, проверить редиректы с UTM и отсутствующие маршруты. Успешный GitHub Pages не доказывает обновление основного сайта.

Секреты, закрытые отчёты, данные гостей и cookies не публиковать в репозитории. Не менять работающие A4 REST AI службы, чужие браузерные профили, тарифы и DNS при обычном обновлении сайта.
