# BRAVIS — статус и инструкция запуска

Проект: ресторан BRAVIS, Москва, улица Расковой, 20.
Действующий код: `site/`. Источники меню — два публичных Яндекс Диска владельца.
Предыдущие серверные скрипты в `scripts/` оставлены для истории; **не запускать их повторно**.

## Готово в GitHub
- Пять мобильных страниц, брендовый дизайн, меню, банкеты, контакты, политика данных (черновик).
- Исходники читаемыми файлами, без дорогостоящего OpenCode.
- Сборка чистым Python 3.12+, без npm, платных API и серверов.
- Сборка и тесты: Actions → `Validate BRAVIS website`.
- Импорт реальных материалов: Actions → `Prepare BRAVIS approved media and website`.
- Из меню — только утверждённые исходники: сезонное JPG, лицевое PDF, оборот JPG, бизнес PDF, детское PDF; `.ai` не использовать.
- Импорт PDF с удалением визуально одинаковых страниц, без открытия многополосных PDF в браузере.
- Пять обложек меню, доступный просмотр с клавиатуры и на телефоне.
- Фотографии из «Фото заведения внутри и снаружи». Новые снимки не подменяют фотографии еды.
- Индексация выключена, пока сайт не готов к запуску.

## Требуется от владельца перед публикацией
1. Зарегистрировать `bravisrest.ru` и подтвердить владение доменом; не покупать отдельный хостинг.
2. Получить реальный restaurant ID/ссылку официального виджета Яндекс СмартРезерв (не отправлять пароли).
3. Уточнить актуальные часы работы, телефон и предложения бизнес-ланча/сезонного меню.
4. Предоставить юридическое наименование оператора персональных данных и публичный контакт.
5. Создать/назначить счётчики Яндекс Метрики и, при желании, GA4; предоставить только публичные ID.
6. Подключить Яндекс Бизнес/Вебмастер и Google Search Console; подтвердить сайт.
7. Утвердить юридические тексты и проверить согласия на обработку данных.

## Подготовка для теста из репозитория
```bash
cd site
python3 src/build.py
python3 scripts/render_menu_gallery.py
python3 verify.py
```
Результат лежит в `site/dist/`. Для проверки можно использовать `python3 -m http.server 8080 -d dist` — только на локальной машине, не как публичный сервер.

Если GitHub Actions импортировал media-файлы, они находятся в `site/public/menu-media/` и `site/public/uploads/`. Иначе будет безопасный placeholder и телефон, а не придуманное меню.

## Производственная публикация (только после подтверждения владельца)
- В `site/site.config.json` установить `domain=https://bravisrest.ru`, `public=true` и реальные идентификаторы.
- Настроить DNS A/AAAA по проверенному IP нового сайта, TLS (Let's Encrypt), `www` → основной домен.
- Перенести только `site/dist/` в отдельный web-root BRAVIS после резервной копии.
- Сверить HTTPS, отображение пяти меню, фото, контакты, кнопки бронирования и согласие на аналитику.
- Проверить `robots.txt`, `sitemap.xml`, canonical, коды ответа 200 и 404, микроразметку Restaurant и мобильную скорость.
- Добавить сайт в Метрику, Вебмастер, GSC, Яндекс Бизнес, 2ГИС; цели: звонок, меню, открытие бронирования, подтверждённая бронь **только при реальном callback**.
- Убрать старые дублирующие материалы и перенаправить страницы лишь при наличии прав на домен прежней площадки.
- Не менять A4 REST AI или амстердамский Telegram gateway.

## Важно
Текстовая SEO-категоризация блюд и цены добавляются только из проверенного оригинала, без OCR-догадок. Детское меню обязательно из PDF. Скриншоты подтверждают, что PDF бизнес-ланча содержит 20 повторяющихся страниц, а не «пустой» документ.
