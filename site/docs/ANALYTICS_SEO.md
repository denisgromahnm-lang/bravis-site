# BRAVIS: реклама, аналитика и индексация

## Что подключено на сайте

Единый загрузчик Яндекс Метрики **113768615** находится в `public/assets/site.js`. Он загружает счётчик только после «Разрешить». Отказ сохраняется; если браузер блокирует хранилище, согласие действует только на текущей странице. Настройки доступны в подвале. Второй код Метрики, отдельный пиксель Директа и `noscript` до согласия не нужны.

Используется официальный [альтернативный домен загрузчика](https://yandex.ru/support/metrica/ru/general/alternative-domain) `mc.yandex.com`: при проверке `mc.yandex.ru` возвращал ошибку сертификата. Номер счётчика и цели сохранены; проверка TLS остаётся включённой.

В кабинете счётчика проверены домен `bravisrest.ru`, часовой пояс Москва и три JS-цели:

| Событие | ID цели | Что означает |
|---|---|---|
| `menu_open` | 674144529 | Нажатие на ссылку меню |
| `phone_click` | 674144588 | Нажатие на телефон, а не состоявшийся звонок |
| `reserve_click` | 674143483 | Переход к внешней форме, а не подтверждённая бронь |

В кабинете также есть автоматическая цель телефона. При отчётности не суммировать её с `phone_click` как два разных обращения. Детальные события кнопок доступны через `data-track`: `banquet_phone_click`, `lunch_phone_click`, `delivery_click`, `loona_signup_click`, `menu_open_*`, `social_*_click`, `reviews_click`, `map_load`, `rating_load`. Для отчёта по ним нужно создать соответствующие цели в кабинете; наличие события в коде само по себе не создаёт цель.

Браузерные проверки подтверждают загрузку после согласия, отправку вызовов и отказ без ошибок. Приём событий сервером Метрики, атрибуция и статистика проверяются отдельно на опубликованном домене. Тестовая очередь `ym.a` не является доказательством приёма конверсии.

## Как запускать контекстную рекламу

1. В существующем кабинете Директа проверить связь кампании со счётчиком 113768615, доступы, цели и автоматическую разметку `yclid`. Это кабинетная настройка, отдельный JS для Директа на сайте не требуется.
2. Разделить кампании по намерению: ресторан/кухня → `/`, обеды → `/lunch/`, банкеты → `/banquets/`. Использовать реальные меню, условия и географию; не обещать неподтверждённые скидки или часы ланча.
3. Согласовать бюджет, ограничения и объявления до запуска. Сам технический выпуск сайта не запускает рекламу.
4. Применять единые метки, например `https://bravisrest.ru/lunch/?utm_source=yandex&utm_medium=cpc&utm_campaign=lunch&utm_content=ad1`. Метрика распознаёт UTM после согласия. Не добавлять в URL имена, телефоны и другие личные сведения. Не заменять выдуманными метками системный `yclid`.
5. Проверить реальный визит с метками и согласие, затем поступление выбранных целей. На старте считать стоимость целевого обращения; не выдавать стоимость клика «Забронировать» за стоимость пришедшего гостя.

Отказ от аналитики и блокировщики уменьшают измеряемую выборку. Это учитывается при сравнении отчётов с фактическими обращениями.

## Что нужно для сквозной аналитики

Сейчас цепочка «расход → визит → подтверждённая бронь → визит в ресторан → оплаченный чек» **не замкнута**. Сайт не получает результат внешней формы и не записывает бронь или выручку. Произвольный скрипт на сайте этого не исправит.

Нужна документированная интеграция СмартРезерва/CRM и учёта: ID обращения/брони, время, статус (подтверждена, отменена, пришёл), идентификатор атрибуции (`ClientID`, `UserID`, `Yclid` или другой поддерживаемый Яндексом), затем ID заказа/чека и фактическая сумма. Сначала подтвердить возможность связать идентификатор с внешней формой; не добавлять в URL СмартРезерва выдуманные параметры. После проверки передавать офлайн-конверсии и доход через поддерживаемую интеграцию/API с защитой от дублей. Доступы должны оставаться на сервере, а не в JS сайта.

Для доказанного результата телефонных обращений потребуется интеграция телефонии/коллтрекинга. Для переписки — связанная запись обращения в CRM; нажатие на WhatsApp/Telegram ещё не означает отправленное сообщение. Новые платные сервисы и подписки отдельно согласуются.

Основные показатели: расходы, обращения, подтверждённые брони, пришедшие гости, оплаченная выручка, стоимость привлечённого гостя. ROMI можно считать после согласования затрат и маржинальности; выручка сама по себе не прибыль.

## Техническое SEO

- Основной адрес — `https://bravisrest.ru/`; canonical указывает на него. Предпросмотр GitHub Pages остаётся `noindex`.
- Основные страницы доступны в HTML без выполнения JS. Есть уникальные title/description, один H1, текстовое меню и ланч по дням, внутренние ссылки, реальные фотографии с alt.
- `Restaurant` содержит подтверждённые адрес, телефон, почту, ежедневные часы 11:00–23:00, кухню, меню, бронирование и `sameAs` на проверенные карточки/сообщества. Чужой рейтинг не выдаётся за собственный `aggregateRating` в разметке.
- Публичные `robots.txt` и `sitemap.xml` разрешают обход. Метатег Яндекс Вебмастера добавлен. Само наличие метатега не доказывает подтверждение прав или индексацию в кабинете.
- `404.html` имеет `noindex`, без canonical. На Timeweb применены настройки без SPA Fallback; отсутствующая страница и файл возвращают настоящий HTTP 404. Реальные маршруты должны сохранить HTTP 200.
- Права в Яндекс Вебмастере подтверждены HTML-файлом. В момент настройки раздел Sitemap временно доступен только для чтения со стороны Яндекса: ручная отправка остаётся незавершённой, sitemap доступен через robots.txt. После восстановления отправить sitemap и проверить диагностику обхода; Google Search Console подключать отдельно при наличии доступа. Позиции и срок индексации не гарантируются кодом.
- Для локального поиска сверить официальный URL, адрес, телефон и расписание в Яндекс Бизнесе и 2ГИС. Не создавать дубли карточек и страницы с повторяющимися ключевыми словами.

## Соцсети, сообщения, карты

Telegram `t.me/bravisrest` и VK `vk.com/bravisrest` подтверждены публичной карточкой ресторана. Рабочий номер WhatsApp и Telegram подтверждён владельцем. Instagram и точный адрес профиля MAX требуют подтверждения; Viber и новые сообщества пока не опубликованы.

Официальный виджет Яндекса показывает текущий рейтинг, без вручную записанных оценок/количества отзывов. Карта и рейтинг загружаются только по отдельному нажатию с объяснением передачи технических данных. Это не включает Метрику и не меняет выбор аналитики. Ссылки на карточку и отзывы доступны сразу. Отметка «Хорошее место · 2026» относится к указанному году, не является бессрочным обещанием.
