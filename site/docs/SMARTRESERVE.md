# BRAVIS — Яндекс СмартРезерв и iiko

Статус: настройка формы **на сайте подготовлена в GitHub**, интеграция между СмартРезервом и iiko выполняется владельцем в соответствующих кабинетах. Реальная бронь пока не протестирована.

## Идентификаторы (не путать)

- **СмартРезерв — ID ресторана:** `5b1e469e-871a-4eb8-bd2a-787ec2d011c3`. Используется только для официальной формы бронирования на сайте.
- **iiko — ID, предоставленный владельцем:** `503266819`. Какого именно объекта iiko этот ID (организация, точка и т. п.) — ещё не проверено. **Нельзя** использовать его в URL формы СмартРезерва.
- В `site/site.config.json` значение `smartReserveId` равно UUID СмартРезерва. ID iiko **не требуется** в браузерном коде сайта.

## Подключение сайта

Согласно [официальной инструкции Яндекса](https://yandex.ru/support/reservation/ru/form), для внешней формы используется URL:
`https://reservation.yandex.ru/partner-reserve/forms/5b1e469e-871a-4eb8-bd2a-787ec2d011c3`

Пять страниц BRAVIS используют этот адрес для кнопок «Забронировать». Форма открывается в новой вкладке. Событие `reserve_click` — **переход к бронированию**, а не подтверждение создания брони.

Всё это можно собирать в GitHub при неактивном домене: `public=false`, `noindex`. Никаких ключей iiko или Яндекс в публичном репозитории нет.

## Подтверждение работы (после настройки владельцем)

1. Открыть форму по URL выше, убедиться, что виден **BRAVIS** и корректная дата, число гостей и свободные столы.
2. В кабинете СмартРезерва проверить, что верно настроены зал, столы, часы работы, доступные интервалы и способ подтверждения.
3. Завершить интеграцию СмартРезерва с iiko по инструкции провайдеров: подтвердить правильную организацию/точку и права доступа. Любые API-ключи и секреты хранить только в защищённых настройках интеграции, **не в GitHub**.
4. Провести согласованное тестовое бронирование и проверить его появление в СмартРезерве, а также передачу в iiko **если конкретная интеграция предполагает передачу резервов**. Удалить или отменить тестовую бронь, чтобы не занимала стол.
5. Зафиксировать подтверждённый результат, прежде чем разрешать официальную публикацию сайта.

Статус интеграции сайт ↔ СмартРезерв: **код подключён, фактическая форма требует ручной проверки**.
Статус интеграции СмартРезерв ↔ iiko: **в процессе у владельца, не подтверждён**.
