# BRAVIS — официальный сайт ресторана (предпросмотр)

Рабочий статический проект без зависимости от npm, создан для ресторана BRAVIS на улице Расковой, 20, Москва.

## Развернуть безопасный предпросмотр на уже настроенном Timeweb

Существующая директория: `/home/a4dev/bravis-site/dist`. Прямая загрузка с ноутбука не нужна.

В веб-консоли российского VPS:

```bash
curl -fsSLo /tmp/bravis-deploy.sh https://raw.githubusercontent.com/denisgromahnm-lang/bravis-site/a227fe66184cfac942017b17b84e29aa7a69c248/scripts/deploy-preview.sh && bash /tmp/bravis-deploy.sh
```

Скрипт:
1. При запуске от root переключается на пользователя `a4dev` (при наличии `runuser`).
2. Загружает **закреплённую по коммиту** версию архива `81d627d` и проверяет SHA-256.
3. Загружает до 12 фотографий из публичного Яндекс Диска в каталог релиза.
4. Собирает и проверяет HTML/CSS/JS и локальные пути картинок.
5. Делает резервную копию старого `dist`, обновляет содержимое **внутри существующей директории**. Туннель предпросмотра, DNS, сервисы A4 REST AI и настройки сервера не меняет.

После выполнения откройте существующую защищённую ссылку Cloudflare и нажмите **Ctrl+F5**.

## Статус

- Пять страниц: главная, меню, банкеты, контакты, политика данных.
- Сборка и локальная проверка статических файлов пройдены.
- До получения ID СмартРезерва бронирование по телефону (не выдается за онлайн-бронь).
- Меню и цены пока отсутствуют, нельзя публиковать фиктивные позиции.
- До подтверждения реквизитов и юридического текста политика данных — черновик.
- Индексация тестовой версии отключена (`noindex`).
- Развертывание на VPS и работа Cloudflare должны быть подтверждены отдельно.

## Исправление пустых PDF в просмотрщике Chrome (24 октября 2026)

У некоторых утверждённых PDF меню BRAVIS в браузере пустые страницы и тёмный фон. Не следует помещать PDF-виджет на страницу: файлы нужно растеризовать в JPEG для гостей.

Готовые инструменты:
- [scripts/render_menu_pdf_as_images.py](scripts/render_menu_pdf_as_images.py): проверяет, что изображения страниц не пустые, конвертирует PDF через `pdftoppm`, сохраняет оригиналы вне public.
- [scripts/install_menu_pdf_images.sh](scripts/install_menu_pdf_images.sh): проверяет hostname российского VPS, при необходимости ставит пакет `poppler-utils`, создаёт и проверяет страницу меню, обновляет защищённый предпросмотр (но не production).

Одна команда на российском сервере:

```bash
curl -fsSLo /tmp/bravis-menu-images.sh https://raw.githubusercontent.com/denisgromahnm-lang/bravis-site/66d391879a8e505ae3cad66b203248e9f80e57e6/scripts/install_menu_pdf_images.sh && bash /tmp/bravis-menu-images.sh
```

Важно: если сам исходный PDF пуст или неправильно экспортирован и Poppler тоже не увидит содержимого, публикация остановится с диагностикой. В этом случае используем **только утверждённую** печатную JPEG-версию соответствующего меню с публичного диска, а не случайные альтернативы.


## Меню: исправление дублирующихся страниц (v3, 24 октября 2026)

Утвержденные PDF из резервной копии отображались некорректно в браузере: основной PDF содержал две повторяющиеся страницы, а PDF бизнес-ланча — двадцать. Сам бизнес-ланч **не пустой**, его меню показано в предоставленных скриншотах.

Исправление в `scripts/fix_menu_duplicates_v3.py.gz.b64` и `scripts/install_menu_v3.sh`:
- проверка изображений всех страниц PDF, удаление **одинаковых** визуальных копий;
- оригинальные PDF только из `.menu-backups`, не из произвольных файлов;
- пять разделов с изображениями-обложками: сезонное, основное, барная карта, бизнес-ланч, детское;
- никакие новые фотографии блюд не назначаются;
- исходные меню и прежнее состояние сохраняются в резервной директории;
- проверка локальной сборки и наличия карточек до установки;
- никакой индексации или изменений DNS.

На российском Timeweb VPS выполнить:

```bash
curl -fsSLo /tmp/bravis-menu-v3.sh https://raw.githubusercontent.com/denisgromahnm-lang/bravis-site/d81e68f916ad5eb704e81fc8e8e221e6c1ac054d/scripts/install_menu_v3.sh && bash /tmp/bravis-menu-v3.sh
```

Установщик скачивает закреплённый по коммиту payload, проверяет SHA-256 исходного скрипта и запускает его. Если страницы окажутся реально разными или появится несоответствие, операция останавливается без обновления действующего предпросмотра.

Проверено на локальном тестовом проекте: два одинаковых листа сводятся к одному, двадцать одинаковых листов — к одному; сборка и проверка пяти страниц пройдены. Проверка на реальных PDF выполняется на VPS.
